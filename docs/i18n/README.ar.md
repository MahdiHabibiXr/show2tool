## حوّل عرضاً عملياً إلى شيء يمكنك التحقق منه

**يستكشف Show2Tool فكرة بسيطة: اعرض سير عمل في المتصفح، وحدد مدخلاته، وأثبت صحة النتيجة بمثال لم يسبق له رؤيته.**

يلتقط النموذج الأولي الحالي حركة API من جلسة Chrome معزولة، ويستنتج روابط بسيطة للمدخلات، ثم يعيد تنفيذها على تطبيق اصطناعي. ويختبر أيضاً الموافقات أحادية الاستخدام والتحقق بالقراءة اللاحقة لعمليات إنشاء وتحديث محدودة النطاق.

الهدف على المدى الأطول هو مهارة محلية وواجهة سطر أوامر تصدّران أدوات CLI/MCP قابلة لإعادة الاستخدام. **مسار التصدير هذا لم يُبنَ بعد.** يجري بناء إصدار ألفا يعطي الأولوية لاستخدام الوكلاء، لكنه غير متاح حتى الآن.

> [!IMPORTANT]
> **نموذج أولي بحثي، وليس أتمتة جاهزة للإنتاج.** لا تُدعم إلا بيئات اختبار محلية اصطناعية. لا تستخدم هذا النموذج الاستكشافي مع حسابات حقيقية. لا يتوفر إصدار منشور على npm ولا خادم MCP قابل للتثبيت.

</div>

## البدء السريع

**المتطلبات:** Node.js بالإصدار 24 أو أحدث، وnpm، وGoogle Chrome. Windows هو النظام الذي تُجرى عليه الاختبارات فعلياً حالياً؛ ويستخدم أحد اختبارات تكامل CDP مسار تثبيت Chrome القياسي على Windows.

</div>

```sh
git clone https://github.com/MahdiHabibiXr/show2tool.git
cd show2tool
npm ci --ignore-scripts
npm run demo
```

<div dir="rtl">

يفتح العرض التوضيحي ملفاً شخصياً مؤقتاً ومعزولاً في Chrome بوضع **بلا واجهة رسومية (headless)**، ويعرض عمليتي بحث، ثم يتحقق من ثالثة. لا يصل إلى ملف Chrome الشخصي المعتاد لديك ولا يتطلب مفتاح API لنموذج.

### ما الذي يظهر عند نجاح التشغيل

</div>

```json
{
  "status": "passed",
  "scope": "synthetic fixture only",
  "trainingInputs": ["alpha", "beta"],
  "heldOutInput": "gamma",
  "resultIds": ["a3"],
  "writes": 0,
  "captureRows": 2
}
```

<div dir="rtl">

*حقول مختارة من مخرجات العرض التوضيحي. تختلف الأزمنة وأعداد البايتات وبصمات العقد باختلاف التشغيل. هذا ليس اختباراً معيارياً للأداء.*

### احتفظ بالأدلة وافحصها

</div>

```sh
# Choose a directory that does not exist yet.
npm run demo -- --out my-new-evidence

# Group captured endpoints without returning approved scalar values.
npm run cli -- inspect my-new-evidence/recording.json

# Inspect the parameter mapping learned from annotated demonstrations.
npm run cli -- infer my-new-evidence/demonstrations.json
```

<div dir="rtl">

تحتوي الملفات الناتجة المحفوظة على تسجيلات اصطناعية وعروض عملية مشروحة وتقرير نتائج، وليست أداة تنفيذية مُصدَّرة. لا تُستبدل الأدلة الموجودة أبداً.

</div>

## آلية العمل

عرضان عمليان ← معالجة محلية ← تحقق بمدخل محجوز لم يُستخدم في التدريب:

</div>

```text
  Two demonstrations           Local processing              Held-out check
 ┌───────────────────┐       ┌────────────────────┐       ┌──────────────────┐
 │ Search for alpha  │       │ Scope API traffic  │       │ Search for gamma │
 │ Search for beta   │ ────▶ │ Infer q → query    │ ────▶ │ Expect record a3 │
 └───────────────────┘       │ Freeze contract    │       │ Check effects    │
                             └────────────────────┘       └──────────────────┘
```

<div dir="rtl">

في المخطط أعلاه، يُعرض البحث عن `alpha` و`beta`؛ ثم تُحدَّد حركة API ضمن نطاق معين، ويُستنتج الربط `q → query`، ويُثبَّت العقد؛ وبعد ذلك يُختبر البحث عن `gamma` مع توقع السجل `a3` وفحص الآثار.

1. **راقب، ولا تُعِد التنفيذ.** يلتقط CDP الطلبات المعروضة ضمن نطاق الإطار الرئيسي المحدد، من دون إصدار عمليات كتابة إضافية.
2. **أبقِ الأدلة صغيرة الحجم.** الملخصات التي تعطي الأولوية للمخطط البنيوي هي الوضع الافتراضي. تتطلب القيم القياسية في الاستعلام أو متن الطلب قائمة سماح صريحة.
3. **ارفض الالتباس.** لا تُعد المدخلات المتطابقة المتعددة أو الأمثلة التي لم تتغير ربطاً قابلاً للتعميم.
4. **اختبر مدخلاً جديداً.** توفر بيانات بيئة الاختبار، التي جرى تهيئتها بصورة مستقلة، النتيجة المتوقعة.
5. **تعامل مع الكتابة بصورة منفصلة.** تحتاج الكتابة إلى نية أحادية الاستخدام ذات صلاحية محدودة، مرتبطة بالوجهة والمستأجر والتغيير المقترح بدقة.

لا تكفي حالة HTTP 200 وبنية JSON صحيحة: تتحقق الاختبارات أيضاً من السجلات المحددة والمستأجر وإصدار التحديث والآثار الفعلية.

</div>

## المنفّذ والمخطط له

| الإمكانية | الحالة الحالية |
| :--- | :--- |
| Chrome معزول + التقاط CDP | **منفّذ ومجرَّب محلياً** |
| نطاق الإطار الرئيسي وحدود المدة والاحتفاظ | **منفّذ**، مع علامات صريحة تشير إلى عدم الاكتمال |
| استنتاج معاملات الاستعلام وحقول الإنشاء القياسية من عرضين | **منفّذ لبيئات الاختبار الاصطناعية** |
| إعادة التنفيذ بمدخل غير مسبوق واعتمادية البحث → التفاصيل | **منفّذ لبيئات الاختبار الاصطناعية** |
| نيات إنشاء/تحديث مرتبطة بالوجهة وقراءة لاحقة | **منفّذ ومختبَر**، مع مُكيِّف موافقة محقون |
| انتهاء العملية بعد تثبيت التغيير → نتيجة مجهولة، بلا إعادة إرسال | **مختبَر بعدّاد مستقل للآثار** |
| أمرا `inspect` الموجز و`infer` للعروض المشروحة | **منفّذ** |
| التأكيد البشري في الطرفية | أداة مساعدة متاحة؛ **التجربة المباشرة بمشاركة إنسان لم تُنجز بعد** |
| مُصرِّف عام لسير عمل المواقع | **مخطط له** |
| تصدير CLI/MCP قابل للتنفيذ والنقل | **مخطط له** |
| وسيط تأكيد بين العمليات ومهارة عامة | **مخطط له** |

</div>

## نموذج السلامة

### محلي افتراضياً

- لا خدمة مستضافة، ولا حلقة نموذج مضمّنة، ولا مفتاح API منفصل للذكاء الاصطناعي.
- ملفات شخصية مؤقتة؛ من دون نسخ قواعد بيانات ملفات تعريف الارتباط أو ملف Chrome الشخصي اليومي لديك.
- إعادة التنفيذ مقصورة على الأصول الاصطناعية المسجلة في العملية نفسها.
- بيانات الاعتماد الطُعمية المستخدمة لكشف التسرب هي بيانات اختبار، وليست بيانات اعتماد لخدمة حقيقية.

### آثار صريحة

- لا يعيد التسجيل تنفيذ عمليات الكتابة المعروضة.
- تنتهي صلاحية نية الكتابة وتُستهلك مرة واحدة؛ ويجب تطابق الوجهة والمستأجر.
- تتحقق التحديثات ذات الإصدارات والقراءة اللاحقة مما حدث فعلياً.
- يؤدي فقدان إقرار الاستلام أو انقطاع الإرسال إلى حالة **مجهولة**، وليس إلى إعادة محاولة تلقائية أبداً.
- لا يوجد تراجع تلقائي: الإجراء التعويضي سيكون عملية كتابة منفصلة.

### حدود موضَّحة بصدق

هذه فحوص لمنع الحوادث، **وليست عزلاً على مستوى نظام التشغيل في مواجهة عملية غير مقيّدة تعمل تحت المستخدم نفسه**. قد يخزّن CDP البيانات مؤقتاً قبل فحوص التطبيق؛ ولا تمثل حدود الاحتفاظ سقفاً صارماً لكل ذاكرة Chrome أو استقبال بيانات الشبكة. لا تستطيع التصفية بحسب أسماء المفاتيح اكتشاف جميع الأسرار أو حقول البيانات الشخصية.

المدفوعات والحذف وتغييرات الصلاحيات والعمليات الجماعية وأتمتة الحسابات الحقيقية والإرسال أو النشر الخارجي تقع خارج نطاق النموذج الأولي الحالي.

## جرّب أداة فحص التأكيد البشري

شغّل الأمر في طرفية تفاعلية فعلية:

</div>

```sh
npm run probe:manual
```

<div dir="rtl">

تعرض الأداة الوجهة والمستأجر وعملية الإنشاء الاصطناعية الدقيقة. اكتب عبارة `approve <intent-id>` المطلوبة لإنشاء **مهمة اختبار مؤقتة واحدة**، أو أي شيء آخر للرفض. تُرفض المدخلات غير التفاعلية قبل بدء بيئة الاختبار.

لا تحل الاختبارات الآلية لمُكيِّف الموافقة محل تشغيل مباشر بمشاركة إنسان. لا يزال فحص الجدوى هذا مفتوحاً.

## التطوير

</div>

```sh
npm run typecheck
npm test
```

<div dir="rtl">

تغطي الاختبارات نطاق المتصفح، والروابط الملتبسة، وإخفاقات المستأجر/المصادقة، وحالات عدم التطابق الدلالي، وتقسيم النتائج إلى صفحات ضمن حدود، وإعادة استخدام الموافقة، وتضخم البيانات عند فك gzip، وعمق JSON، والاستجابات المتوقفة، والإنهاء الفعلي للعملية الفرعية في مراحل محيطة بالإرسال.

> [!NOTE]
> لوحظ إخفاق متقطع في اختبار الإرسال المتزامن، ولم يُحدَّد سببه الجذري بعد. عمليات التشغيل الناجحة دليل على تلك العمليات نفسها، وليست ضماناً للجاهزية للإنتاج.

</div>

## الفرق عن CLI-Anything

يبني [CLI-Anything](https://github.com/HKUDS/CLI-Anything) واجهات سطر أوامر ملائمة للوكلاء انطلاقاً من قواعد شيفرة البرامج أو واجهات API الموجودة. يبدأ Show2Tool من **حركة المتصفح/API الناتجة عن عرض عملي**، ويبحث في تعميم المعاملات والتأكيد الصريح للكتابة والتحقق المستقل من النتائج.

يشترك المشروعان في جعل البرامج قابلة للاستخدام بواسطة الوكلاء. لكنهما ليسا التطبيق نفسه، ولا يضمّن Show2Tool مشروع CLI-Anything. هذا الاختلاف فرضية للمنتج، وليس ادعاءً بأن المشاريع الأخرى تفتقر إلى التحقق.

## المساهمة

تفيد حالات إعادة الإنتاج المركّزة: ربط ملتبس للمدخلات، أو علامة حذف مفقودة، أو نتيجة خاطئة، أو تراجع في حماية الخصوصية. استخدم بيانات اصطناعية، وأبلغ عن الأمر والبيئة والنتيجة المتوقعة والنتيجة الفعلية. لا ترفق أبداً ملفات تعريف الارتباط أو ملفات المتصفح الشخصية أو حركة الحسابات الخام.

**لم يُختَر ترخيص مفتوح المصدر بعد.** إتاحة الاطلاع على الشيفرة المصدرية لا تمنح حق إعادة توزيعها. لا يزال الترخيص والتحزيم للإصدار العام قرارين مفتوحين.
