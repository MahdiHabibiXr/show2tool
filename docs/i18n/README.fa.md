## یک نمایش عملی را به چیزی قابل بررسی تبدیل کنید

**Show2Tool ایده‌ای ساده را بررسی می‌کند: یک گردش‌کار مرورگر را نمایش دهید، ورودی‌های آن را شناسایی کنید و نتیجه را با مثالی که قبلاً ندیده است، اثبات کنید.**

نمونهٔ اولیهٔ فعلی، ترافیک API را از یک نشست ایزولهٔ Chrome ثبت می‌کند، نگاشت‌های سادهٔ ورودی را استنباط می‌کند و آن‌ها را روی یک برنامهٔ ساختگی بازپخش می‌کند. همچنین تأییدهای یک‌بارمصرف و راستی‌آزمایی با بازخوانی را برای عملیات محدودِ ایجاد و به‌روزرسانی آزمایش می‌کند.

هدف بلندمدت، یک مهارت محلی و رابط خط فرمان است که ابزارهای قابل استفادهٔ مجددِ CLI/MCP را خروجی بدهند. **این خط لولهٔ خروجی‌گیری هنوز ساخته نشده است.** نسخهٔ آلفا با اولویت استفاده توسط عامل‌ها در حال ساخت است، اما هنوز در دسترس نیست.

> [!IMPORTANT]
> **نمونهٔ اولیهٔ پژوهشی است، نه اتوماسیون آمادهٔ محیط عملیاتی.** فقط محیط‌های آزمایشی محلی با داده‌های ساختگی پشتیبانی می‌شوند. از این نمونهٔ آزمایشی روی حساب‌های واقعی استفاده نکنید. هیچ نسخه‌ای در npm یا سرور MCP قابل نصبی در دسترس نیست.

</div>

## شروع سریع

**پیش‌نیازها:** Node.js نسخهٔ ۲۴ یا بالاتر، npm و Google Chrome. ویندوز پلتفرمی است که در حال حاضر عملاً روی آن آزمایش انجام می‌شود؛ یکی از آزمون‌های یکپارچه‌سازی CDP از مسیر نصب استاندارد Chrome در ویندوز استفاده می‌کند.

</div>

```sh
git clone https://github.com/MahdiHabibiXr/show2tool.git
cd show2tool
npm ci --ignore-scripts
npm run demo
```

<div dir="rtl">

دمو یک نمایهٔ موقت و ایزولهٔ Chrome را در حالت **بدون رابط گرافیکی (headless)** باز می‌کند، دو جست‌وجو را نمایش می‌دهد و سومی را بررسی می‌کند. به نمایهٔ معمول Chrome شما دسترسی ندارد و به کلید API مدل نیاز ندارد.

### خروجی یک اجرای موفق

</div>

```json
{
  "status": "passed",
  "scope": "synthetic fixture only",
  "trainingInputs": ["alpha", "beta"],
  "heldOutInput": "gamma",
  "resultIds": ["a3"],
  "writes": 0,
  "captureRows": 2
}
```

<div dir="rtl">

*فیلدهای منتخب از خروجی دمو. زمان‌ها، تعداد بایت‌ها و هش‌های قرارداد به هر اجرا وابسته‌اند. این یک بنچمارک کارایی نیست.*

### شواهد را نگه دارید و بررسی کنید

</div>

```sh
# Choose a directory that does not exist yet.
npm run demo -- --out my-new-evidence

# Group captured endpoints without returning approved scalar values.
npm run cli -- inspect my-new-evidence/recording.json

# Inspect the parameter mapping learned from annotated demonstrations.
npm run cli -- infer my-new-evidence/demonstrations.json
```

<div dir="rtl">

فایل‌های خروجی ذخیره‌شده شامل ضبط‌های ساختگی، نمایش‌های حاشیه‌نویسی‌شده و گزارش نتیجه‌اند؛ نه یک ابزار اجراییِ خروجی‌گرفته‌شده. شواهد موجود هرگز بازنویسی نمی‌شوند.

</div>

## نحوهٔ کار

دو نمایش عملی → پردازش محلی → بررسی با ورودی کنارگذاشته‌شده از آموزش:

</div>

```text
  Two demonstrations           Local processing              Held-out check
 ┌───────────────────┐       ┌────────────────────┐       ┌──────────────────┐
 │ Search for alpha  │       │ Scope API traffic  │       │ Search for gamma │
 │ Search for beta   │ ────▶ │ Infer q → query    │ ────▶ │ Expect record a3 │
 └───────────────────┘       │ Freeze contract    │       │ Check effects    │
                             └────────────────────┘       └──────────────────┘
```

<div dir="rtl">

در نمودار بالا، دو جست‌وجوی `alpha` و `beta` نمایش داده می‌شوند؛ در پردازش محلی، دامنهٔ ترافیک API محدود می‌شود، نگاشت `q → query` استنباط و قرارداد تثبیت می‌شود؛ سپس جست‌وجوی `gamma` با انتظار رکورد `a3` و بررسی اثرها ارزیابی می‌شود.

1. **مشاهده کنید، نه بازپخش.** ثبت CDP با دامنهٔ محدود به فریم اصلی انتخاب‌شده، درخواست‌های نمایش‌داده‌شده را بدون ایجاد نوشتن‌های اضافی ثبت می‌کند.
2. **شواهد را کم‌حجم نگه دارید.** خلاصه‌های مبتنی بر طرح‌واره، حالت پیش‌فرض‌اند. مقادیر اسکالرِ پارامترهای پرس‌وجو یا بدنه به فهرست مجاز صریح نیاز دارند.
3. **ابهام را رد کنید.** چند ورودی منطبق یا مثال‌های بدون تغییر، نگاشت تعمیم‌یافته محسوب نمی‌شوند.
4. **یک ورودی جدید را آزمایش کنید.** داده‌های محیط آزمایشی که به‌صورت مستقل مقداردهی اولیه شده‌اند، نتیجهٔ مورد انتظار را تأمین می‌کنند.
5. **نوشتن‌ها را جداگانه مدیریت کنید.** هر نوشتن به یک قصدِ یک‌بارمصرف و انقضادار نیاز دارد که به مقصد، مستأجر و تغییر دقیق پیشنهادی مقید باشد.

وضعیت HTTP 200 و ساختار معتبر JSON کافی نیستند: آزمون‌ها رکوردهای انتخاب‌شده، مستأجر، نسخهٔ به‌روزرسانی و اثرهای واقعی را نیز بررسی می‌کنند.

</div>

## پیاده‌سازی‌شده و برنامه‌ریزی‌شده

| قابلیت | وضعیت فعلی |
| :--- | :--- |
| Chrome ایزوله + ثبت با CDP | **پیاده‌سازی و به‌صورت محلی آزمایش شده** |
| دامنهٔ فریم اصلی و محدودیت‌های مدت و نگه‌داری | **پیاده‌سازی شده**، همراه با نشانگرهای صریحِ ناقص‌بودن |
| استنباط پارامتر پرس‌وجو و فیلد اسکالرِ ایجاد از دو نمایش | **برای محیط‌های آزمایشی ساختگی پیاده‌سازی شده** |
| بازپخش با ورودی دیده‌نشده و وابستگی جست‌وجو → جزئیات | **برای محیط‌های آزمایشی ساختگی پیاده‌سازی شده** |
| قصدهای ایجاد/به‌روزرسانیِ مقید به مقصد و بازخوانی | **پیاده‌سازی و آزمایش شده**، با مبدل تأییدِ تزریق‌شده |
| مرگ فرایند پس از ثبت قطعی تغییر → نتیجهٔ نامعلوم، بدون ارسال مجدد | **با شمارندهٔ مستقل اثرها آزمایش شده** |
| دستورهای کم‌حجم `inspect` و `infer` برای نمایش‌های حاشیه‌نویسی‌شده | **پیاده‌سازی شده** |
| تأیید انسانی در ترمینال | ابزار کمکی موجود است؛ **آزمایش زنده با انسان در انتظار انجام است** |
| کامپایلر عمومی گردش‌کار وب‌سایت‌ها | **برنامه‌ریزی‌شده** |
| خروجی اجرایی و قابل حمل CLI/MCP | **برنامه‌ریزی‌شده** |
| واسط تأیید بین‌فرایندی و مهارت عمومی | **برنامه‌ریزی‌شده** |

## مدل ایمنی

### محلی به‌صورت پیش‌فرض

- بدون سرویس میزبانی‌شده، حلقهٔ مدلِ تعبیه‌شده یا کلید API جداگانهٔ هوش مصنوعی.
- نمایه‌های موقت؛ بدون کپی‌کردن پایگاه‌های دادهٔ کوکی مرورگر یا نمایهٔ روزمرهٔ Chrome شما.
- بازپخش فقط به مبدأهای ساختگی ثبت‌شده در همان فرایند محدود است.
- نشانگرهای طعمهٔ اعتبارنامه، دادهٔ آزمایشی‌اند؛ نه اعتبارنامهٔ یک سرویس واقعی.

### اثرهای صریح

- ضبط، عملیات نوشتنِ نمایش‌داده‌شده را بازپخش نمی‌کند.
- قصد نوشتن منقضی می‌شود و فقط یک بار مصرف می‌شود؛ مقصد و مستأجر باید منطبق باشند.
- به‌روزرسانی‌های نسخه‌دار و بازخوانی بررسی می‌کنند که واقعاً چه رخ داده است.
- از دست رفتن رسید تأیید یا قطع ارسال به وضعیت **نامعلوم** منجر می‌شود؛ هرگز به تلاش مجدد خودکار نمی‌انجامد.
- بازگردانی خودکار وجود ندارد: اقدام جبرانی یک نوشتن جداگانه خواهد بود.

### مرزهای صادقانه

این‌ها بررسی‌هایی برای پیشگیری از خطاهای ناخواسته‌اند، **نه ایزوله‌سازی در سطح سیستم‌عامل در برابر فرایند نامحدودی که با همان کاربر اجرا می‌شود**. CDP ممکن است پیش از بررسی‌های برنامه، داده‌ها را در بافر نگه دارد؛ محدودیت‌های نگه‌داری سقف قطعی برای کل حافظهٔ Chrome یا دریافت داده از شبکه نیستند. فیلترکردن بر اساس نام کلید نمی‌تواند همهٔ اسرار یا فیلدهای شخصی را شناسایی کند.

پرداخت، حذف، تغییر مجوزها، عملیات انبوه، اتوماسیون حساب‌های واقعی و ارسال/انتشار خارجی، خارج از دامنهٔ نمونهٔ اولیهٔ فعلی هستند.

## پروب تأیید انسانی را امتحان کنید

در یک ترمینال تعاملی واقعی اجرا کنید:

</div>

```sh
npm run probe:manual
```

<div dir="rtl">

مقصد، مستأجر و عملیات دقیقِ ایجاد ساختگی نمایش داده می‌شود. عبارت درخواستی `approve <intent-id>` را وارد کنید تا **یک وظیفهٔ آزمایشی موقت** ایجاد شود؛ هر ورودی دیگری به معنی ردکردن است. ورودی غیرتعاملی پیش از شروع محیط آزمایشی رد می‌شود.

آزمون‌های خودکار مبدل تأیید جای اجرای زنده با انسان را نمی‌گیرند. این بررسی امکان‌سنجی همچنان باز است.

## توسعه

</div>

```sh
npm run typecheck
npm test
```

<div dir="rtl">

> [!NOTE]

## تفاوت با CLI-Anything

[CLI-Anything](https://github.com/HKUDS/CLI-Anything) از کدبیس‌های نرم‌افزاری یا APIهای موجود، رابط‌های خط فرمان مناسب عامل‌ها می‌سازد. Show2Tool از **ترافیک مرورگر/API حاصل از نمایش عملی** شروع می‌کند و تعمیم پارامترها، تأیید صریح نوشتن و بررسی مستقل نتیجه را بررسی می‌کند.

این پروژه‌ها در قابل استفاده کردن نرم‌افزار برای عامل‌ها هم‌پوشانی دارند. پیاده‌سازی آن‌ها یکسان نیست و Show2Tool شامل CLI-Anything نیست. این تمایز یک فرضیهٔ محصول است، نه ادعایی مبنی بر اینکه پروژه‌های دیگر راستی‌آزمایی ندارند.

## مشارکت

بازتولیدهای متمرکز مفیدند: نگاشت ورودی مبهم، نشانگر حذفِ جاافتاده، نتیجهٔ نادرست یا پسرفت در حریم خصوصی. از داده‌های ساختگی استفاده کنید و دستور، محیط، نتیجهٔ مورد انتظار و نتیجهٔ واقعی را گزارش دهید. هرگز کوکی‌ها، نمایه‌های مرورگر یا ترافیک خام حساب‌ها را پیوست نکنید.

**هنوز هیچ مجوز متن‌بازی انتخاب نشده است.** قابل مشاهده بودن کد منبع به معنی اعطای حق بازتوزیع نیست. مجوز و بسته‌بندی برای انتشار عمومی همچنان تصمیم‌های باز هستند.
