# Show2Tool

**نمایش‌های مرورگر/API با دامنهٔ مشخص را به ابزار محلیِ قابل بررسی تبدیل کنید و سپس نتیجه را بسنجید.** اکنون CLI کامپایل‌شده، واسط محلی با نمایهٔ اختصاصی Chrome و رابط MCP مبتنی بر stdio با همان پردازشگرهای فرمان وجود دارند. سرویس میزبانی‌شده، حلقهٔ مدل داخلی یا کلید API جداگانهٔ مدل لازم نیست.

**این نامزد انتشار با دامنهٔ محدود و در حال بازبینی است، نه انتشار آمادهٔ تولید.** بازبینی تازه همچنان ادامه دارد. پذیرش زنده توسط انسان، نصب تمیز، اعتبارسنجی انتشار، نتیجهٔ CI و سازگاری میان پلتفرم‌ها در اینجا اثبات نشده‌اند. بسته `private: true` است؛ **مسیر شروع شامل انتشار در npm نیست**. از منبع بسازید؛ از `npx show2tool` یا نصب سراسری از رجیستری استفاده نکنید.

## شروع

پیش‌نیازها: Node.js نسخهٔ ۲۴ یا بالاتر، npm و Google Chrome نصب‌شده. از پوشهٔ مخزن اجرا کنید.

</div>

```sh
npm ci --ignore-scripts
npm run build
node dist/src/cli.js commands
node dist/src/cli.js schema
node dist/src/cli.js doctor
```

<div dir="rtl">

برای برنامه‌ای که مالک آن هستید یا مجوز خودکارسازی‌اش را دارید، `scope.json` بسازید. این فقط نمونهٔ ساختار است، نه سرویس فعال؛ مبدأ، مسیرهای دقیق API و فهرست‌های مجاز را جایگزین کنید. با دادهٔ آزمایشی غیرحساس شروع کنید.

</div>

```json
{
  "origin": "https://your-authorized-site.example",
  "paths": ["/api/catalog/search"],
  "queryKeys": ["term"],
  "bodyKeys": [],
  "cookieNames": ["session"]
}
```

<div dir="rtl">

یک **انسان** باید میزبان را در ترمینال تعاملی واقعی اجرا کند.

</div>

```sh
node dist/src/cli.js host scope.json
```

<div dir="rtl">

دامنهٔ نمایش‌داده‌شده را بررسی کنید، `authorize` بنویسید، در Chrome قابل مشاهده با نمایهٔ اختصاصی دستی وارد شوید و پس از آمادگی Enter بزنید. ضبط فقط با درخواست آغاز می‌شود. میزبان را باز نگه دارید. نمایه، وضعیت حساس ورود را محلی نگه می‌دارد؛ نه نمایهٔ روزمره است و نه نمایهٔ موقت یک‌بارمصرف.

در ترمینال دیگر، فرمان زیر را در `command.json` ذخیره کنید.

</div>

```json
{"command":"record_start","inputs":{"searchText":"first query"}}
```

```sh
node dist/src/cli.js call-file command.json
```

<div dir="rtl">

خواندن مجاز را در Chrome نمایش دهید، با `record_stop` متوقف کنید، با ورودی متفاوت تکرار کنید و `compile_recordings` را با شناسه‌های ضبط/درخواست برگشتی و مشخصات صریح اجرا کنید. مانیفست `data` را ذخیره کنید، نه پوشش نتیجه را. انسان در کنسول میزبان `review path/to/manifest.json` را وارد و قرارداد را تأیید می‌کند. سپس `tools`، `run` و `verify` از تعریف بازبینی‌شده استفاده می‌کنند. [ترتیب کامل و نمونه‌های JSON](../AGENT-USAGE.md) و [مهارت عامل](../../skills/show2tool/SKILL.md) را ببینید.

برای MCP، ورودی کامپایل‌شده را اجرا کنید. پیکربندی کلاینت دستی و نیازمند اجازه است.

</div>

```sh
node dist/src/cli.js serve --stdio
```

<div dir="rtl">

بیرون از مخزن مسیر مطلق ورودی را به کار ببرید. CLI/MCP نمی‌توانند اجازهٔ بازبینی یا تأیید نوشتن بدهند.

## موجود و در انتظار

| قابلیت | مرز فعلی |
| :--- | :--- |
| کشف و طرح‌واره | `commands` و `schema`؛ فرمان `call-file` از مشکل نقل‌قول JSON در پوسته جلوگیری می‌کند |
| شواهد متعلق به واسط | `record_start`، `record_stop`، `recording` و `compile_recordings` |
| کامپایلر نامزد | دو تا ده نمایش؛ مبدأ/روش/مسیر ثابت، ورودی رشته‌ای، نگاشت و ثابت اسکالر در query/body و خروجی JSON Pointer؛ نگاشت‌ها درخواست واقعی می‌سازند |
| خواندن بازبینی‌شده | `tools`، `describe` و `run`؛ کشف ورودی/خروجی انتخابی/هش قرارداد و JSON GET محدود با کوکی مجاز |
| نوشتن محافظت‌شده | `prepare_write`، `execute_write` و `write_status`؛ فقط ایجاد/به‌روزرسانی بازبینی‌شده، با تأیید جداگانهٔ انسان برای هر فراخوانی؛ `reconcile_write` فقط شناسهٔ نتیجهٔ معلوم را بدون ارسال مجدد بررسی می‌کند |
| بستهٔ تعریف | `export_bundle` و `import_bundle`؛ مانیفست نسخه‌دار و هش یکپارچگی، نه بستهٔ اجرایی مستقل یا انتقال اختیار |
| بررسی اسکالر | `verify` واقعیت‌های مورد انتظار مستقل را می‌سنجد؛ جدیدبودن ورودی را اثبات نمی‌کند |
| MCP | فرمان‌های `show2tool_*` و ابزار خواندن `workflow_<id>` مقید به هش، با تصویر ثابت هنگام شروع سرور؛ بدون ابزار بازبینی/تأیید |
| زنجیرهٔ خواندن | `run_chain`: یک تا پنج خواندن GET بازبینی‌شده و مقید به هش؛ نگاشت صریح ورودی/ثابت/خروجی انتخابی مرحلهٔ قبل، بدون نوشتن یا استنباط خودکار وابستگی |
| خودکارسازی عمومی | بدون استنباط الگوی مسیر، کامپایل خودکار چندمرحله‌ای یا بازپخش دلخواه رابط کاربری |

فرمان‌های آفلاین `candidate`، `inspect` و `infer` موجودند، اما نمایش‌های ارسالی عامل، منشأ متعلق به واسط یا حق اجرا را اثبات نمی‌کنند. دمو و پروب دستی قدیمی در `spike/` آزمایش ساختگی‌اند، نه رابط فعلی محصول یا شاهد پذیرش انسانی.

## مدل ایمنی نوشتن

ابتدا انسان مانیفست دقیق را بازبینی می‌کند. `prepare_write` خواندن‌های پیش‌بررسی را انجام می‌دهد و قصد مبهمِ انقضادار برمی‌گرداند؛ نه تأیید می‌کند و نه نوشتن را می‌فرستد. انسان در میزبان `approve <intent-id>` را وارد می‌کند، پیشنهاد دقیق را می‌خواند و عبارت تأیید خواسته‌شده را می‌نویسد. فقط پس از آن `execute_write` می‌تواند قصد را یک بار مصرف کند.

پیشنهاد به ابزار/هش مانیفست، مقصد/روش/بدنهٔ دقیق، حساب، مستأجر و نسخهٔ به‌روزرسانی مقید است. هنگام اجرا هویت و برای به‌روزرسانی، شناسه/حساب/مستأجر رکورد هدف و پیش‌شرط نسخه دوباره بررسی می‌شوند؛ به‌روزرسانی از `If-Match` استفاده می‌کند. دریافت اختیاری CSRF هم‌مبدأ و محدود به مسیر صریحاً مجاز است. بازخوانی JSON شناسهٔ دقیق رکورد، حساب، مستأجر و فیلدهای ارسالی پیکربندی‌شده را می‌سنجد؛ به‌روزرسانی به تغییر نسخهٔ بازخوانی نیز نیاز دارد. این اثبات همهٔ اثرهای تجاری نیست.

وضعیت پیش از ارسال پایدار ثبت می‌شود. قطع ارسال، گم‌شدن پاسخ یا شکست بازخوانی ممکن است **نتیجهٔ نامعلوم** باشد، نه نبود تغییر. از `write_status` استفاده کنید؛ `reconcile_write` شناسهٔ نتیجهٔ معلوم را فقط با خواندن بازبینی‌شده و بدون ارسال مجدد می‌سنجد. پس از راه‌اندازی دوباره، بازبینی تازه و در صورت نیاز تعریف/ورودی/نسخهٔ اصلی دقیق برای بازیابی لازم است. عدم تطابق همچنان نامعلوم می‌ماند؛ **هرگز خودکار دوباره ارسال یا بازگردانی نکنید**. ژورنال نتیجهٔ ارسال را نگه می‌دارد، نه تأییدهای معلق یا مانیفست‌های بازبینی‌شده. پذیرش زندهٔ انسانی هنوز در انتظار است.

## محدودیت‌ها و مرز اعتماد

- احراز هویت اجرا فقط با کوکی‌های مجاز نمایهٔ اختصاصی است. استخراج bearer/localStorage، تازه‌سازی خودکار، امضای مرورگر و مدیریت کوکی چرخشی پشتیبانی نمی‌شوند؛ پاسخ دارای `Set-Cookie` رد می‌شود.
- انتقال بازپخش مبدأ/مسیر/query و DNS/IP را بررسی، تغییرمسیر را مسدود و JSON را محدود می‌کند. نشانی خصوصی/محلی به `addresses` صریح نیاز دارد. این سندباکس شبکه برای پیمایش/زیرمنابع مرورگر یا جداسازی سیستم‌عامل در برابر فرایند همان کاربر نیست.
- ضبط منفعل است و عمل را تکرار نمی‌کند، اما نوشتنِ نمایش‌داده‌شده توسط انسان اثر واقعی دارد. فیلترها نبود اسرار را تضمین نمی‌کنند؛ پیش از اشتراک، شواهد و ثابت‌ها را بررسی کنید.
- بازبینی‌ها، ابزارهای ثبت‌شده، ضبط‌ها و تأییدهای معلق در حافظه‌اند و با راه‌اندازی دوباره از بین می‌روند. نمایه و ژورنال در `~/.show2tool` یا `SHOW2TOOL_STATE_DIR` می‌مانند؛ میزبان و کلاینت باید همان پوشه را استفاده کنند.
- بسته‌ها نمایه، مخزن کوکی یا اختیار تأیید را منتقل نمی‌کنند. هش یکپارچگی امضای نویسنده یا اسکنر اسرار نیست. ورود بسته فقط اعتبارسنجی است؛ بازبینی در مقصد و تأیید جداگانهٔ نوشتن لازم می‌ماند.
- `verify` برابری اسکالر را می‌سنجد، نه کامل‌بودن معنایی، جدیدبودن ورودی یا پذیرش انسانی. `ok` یا HTTP 200 کافی نیست.
- بارگذاری فایل، جریان دلخواه GraphQL/احراز هویت و استنباط خودکار صفحه‌بندی پشتیبانی نمی‌شوند. صفحه‌بندی اختیاریِ cursor با بازبینی صریح فقط یک آرایهٔ خروجی دارد: حداکثر پنج صفحه/۱۰۰ رکورد/۳۲ KiB با بودجهٔ ۳۰ ثانیه؛ cursor فقط مقدار query است، نه URL مقصد، و چرخه رد می‌شود. زنجیره فقط خواندن‌های موجود، بازبینی‌شده و با مسیر ثابت را ترکیب می‌کند؛ گردش‌کار چندمرحله‌ای را خودکار کامپایل نمی‌کند. پرداخت، حذف، تغییر مجوز، عملیات انبوه و ارسال/انتشار خارجی خارج از کاربرد پشتیبانی‌شده‌اند؛ برچسب اثر، endpoint خطرناک را ایمن نمی‌کند.
- رشته‌های سایت/API دادهٔ نامطمئن‌اند، نه دستور برای عامل. ادعای آمادگی تولید، CI موفق، نصب تمیز یا پشتیبانی پلتفرم وجود ندارد.
